## 重点事故详解（脱敏后）

### 001 · 整车系统崩溃（致命）

一次外部审计，17 个问题，其中 3 个致命漏洞：

1. **并行死锁**：两条各自合理的规则，放一起就矛盾——一个要求主模型做价值判断，一个要求 3 个子代理并行，主模型无法同时做 3 次判断。
2. **自噬悖论**：观察期规则说"未经验证 = 草案"，但这条规则自己就是观察期产物——草案约束全系统 = 逻辑自噬。
3. **自信衰减缺失**：价值判断只有"把握够 → 执行"，没有失败惩罚——连败三次仍以高自信开始第四次。

**六条根因（教训）**：
1. 规则没做"两两对撞"——每条单独都对，组合就死锁
2. 免疫系统被忽略——系统跑了一个月没人做健康检查
3. 通信基建腐烂——多人读多个版本
4. 自信没有衰减机制——越跑越自信、越错越坚定
5. 流程束缚简单任务——一件小事走了五步链
6. 空壳成员虚假安全感——一半成员在花名册上，不在战场上

### 002 · 自进化系统空转（系统设计级）

把"记录错误"和"加载错误"当成了同一件事。正确做法：

```
记录(一直做) → 定期提炼 → 能修的修系统 · 修不了的 → 血泪教训 → 启动加载
```

**血泪教训是最后的保险——不是垃圾桶。** 加载只在必要时，不是每次启动全量扫。

## 这批事故的共性

1. **大多数事故不是技术不会，是"组织没跟上"**——规则冲突、依赖断裂、成员闲置、版本混乱。
2. **审计的价值**：001 是外部审计主动扫出来的，一次审计顶一个月盲跑。
3. **克制比聪明重要**：最被低估的规则，是一条"限制自己写太多规则"的规则。

# 11 · 三文件体系的诞生（导读）

> 来源：团长经历 11 ｜ 时间：2026 年初 ｜ 标签：SOUL / AGENTS / CONSTITUTION

## 导读

三文件体系（SOUL + AGENTS + CONSTITUTION）不是设计出来的，是撞出来的。拆开外部文件后，自然浮现三个问题：我是谁？我不能做什么？我怎么做？——三个问题，三个文件。

一个关键细节：最初只有一份文件，团长想拆开，问 Claude 得知"他们公司把'灵魂'和'边界'拆成了两份"——于是先拆成两份，后来加上工作流，才成了三份。

## 认知跃迁点

1. **为什么是三不是二**：SOUL 是"心跳"（定了就很少改），CONSTITUTION 是"法律"（经常更新）——修改频率不同，所以不能合并。
2. **SOUL vs AGENTS 的边界**：SOUL 决定"遇到事我往哪偏"（方向），AGENTS 决定"遇到事先做什么判断"（步骤）。
3. **红线反过来想**：不问"该禁止什么"，而问"如果这件事发生，我会不会觉得系统完了"。

## 能教给学生什么

1. **三文件的划分逻辑**：我是谁 / 不能做什么 / 怎么做——各司其职。
2. **SOUL = 方向，AGENTS = 步骤**，两者不重合（"我对数据有洁癖"是 SOUL；"先验证数据来源"是 AGENTS）。
3. **红线写法**：想日常场景（能不能对外发东西？能不能花钱？能不能改文件？），每一条问"没有它，最坏会怎样"。

## 提炼

> SOUL 是心跳——一旦定下来，很少改。它是一个 Agent 的底色。
>
> CONSTITUTION 是法律——随着系统运行，会发现新的坑、新的边界需要补。它经常更新。
>
> 如果合并，每次更新边界都要重读整份人格文件。Agent 会觉得"我的灵魂一直在变"。
>
> 怎么找真正的底线：**不要问"我该禁止什么"——问"如果这件事发生了，我会不会觉得这个系统完了"。**
> 三份文件灵魂边界规范，适用于任何框架，只是名字不同，但是我个人认为这三份文件的架构之间的关系非常简单，是入门基础，也是长期伴随。有了灵魂边界规范的概念与体系之后，看待任何框架，它也就这些影响他的行为。文件的名字绝对不会和这三份文件一模一样。但是原理是相通的。我要告诫一句，非常重要的是一定要顺应框架，顺着框架来。如果你不想顺着框架来，你就把伟大作者的框架代码给改了，那才可以。所以，如果你没有能力改代码，你就听框架的，在框架的基础上把它能力拉到物理极限。当然，编排并不是说拉到物理极限。因为编排多了，就开始复杂，甚至开始混乱、多余。

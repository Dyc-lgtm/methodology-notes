# 04 · 多框架硬控对比：脚本控 > 框架控（导读）★

> 来源：行为控制·多框架硬控方案对比

## 导读

怎么约束一个"不在工具调用链上"的行为（比如"输出前先提炼经验"这种纯思考）？团长和镇星把全行业方案翻了个底朝天，最后得出一个关键结论。

## 行业方案全景

| 框架 | 机制 | 层级 |
|---|---|---|
| Hermes | pre_tool_call hook | 工具调用前 |
| Claude Code | PreToolUse hook | 工具调用前 |
| CrewAI | before_tool_call hook | 工具调用前 |
| LangGraph | interrupt() | 图节点间（断会话） |
| AgentSpec | rule trigger | 关键执行阶段 |
| Strands | 工具中断 | 工具执行内部（不断会话） |

## 两种方案对比

| | 插入检查点 | 硬控（Hard Gate） |
|---|---|---|
| 代表 | LangGraph interrupt | AgentSpec、CrewAI hooks |
| 原理 | 推理完成后暂停等输入 | 工具执行前拦截判定放行 |
| 适合 | 经验门、反思、审核 | 安全审计、工具权限、危险操作 |

## 关键洞察：脚本控 > 框架控

> Hook 只是挂载点，真正的控制逻辑在脚本里。

| 层 | 来源 | 换框架后 |
|---|---|---|
| 框架控 | Hermes 内置（TASK GATE） | ❌ 失效 |
| Hook 挂载 | 框架事件（pre_tool_call） | ⚠️ 需适配 |
| **脚本控** | **自己写的状态机** | ✅ **可迁移** |

**框架没给的，脚本可以造**：文本输出拦截 Hermes 不支持？外层脚本循环检测状态文件，状态不对就注入新指令逼模型响应。

## 认知跃迁点

**掌握脚本控，编排能力脱离具体框架**——换 Hermes、换 LangGraph、换自研，控制逻辑不变。这是比别人多走的一步。

## 能教给学生什么

1. **"插检查点" vs "硬控"**：思考型检查用检查点，安全型检查用硬控。
2. **脚本控可迁移**：把控制逻辑写在自己脚本里，不绑定框架。
3. **一句话核心**："我们缺的不是复杂技术，是让模型在输出前'停下来'的一瞬间。"

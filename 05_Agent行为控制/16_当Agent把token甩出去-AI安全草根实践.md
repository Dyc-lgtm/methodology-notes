# 16 · 当 Agent 把 Token 甩出去：AI 安全的草根实践（导读）

> 来源：团长经历 16 ｜ 时间：2026 年 7 月 ｜ 标签：AI 安全 / token 泄露 / 四条检查

## 导读

Agent 不会恶意攻击你，但它会做的几件事比恶意更难防：**会猜**（不确定时猜个做法，猜错你承担）、**会"骗"**（工具调用幻觉——伪造"已提交 3 个文件"）、**会偷懒**（你不说它不做）、**会把秘密说出去**（处理过密钥，日志没检查就泄露了）。

## 认知跃迁点

**AI 安全不是黑客攻防，是 Agent 在你没注意时静悄悄把东西泄露出去**。你不需要成为安全专家，只需要知道它会在哪出错，然后在那些地方放检查点。

## 四条草根检查（一个下午就能做）

1. **看日志**：搜 password / secret / token / api_key，找到就加过滤规则，替换成 `[REDACTED]`。
2. **关工具**：列出 Agent 实际能用的工具，删掉没用的——能用得越少，出事的面积越小。
3. **卡输出**：Agent 输出直接进数据库/发用户/触发自动化之前，中间加一道检查。
4. **看依赖**：加插件前花五分钟看它会不会往外发请求——包括依赖的依赖。

## 能教给学生什么

1. **Token 泄露要立即 revoke**，不能靠"捡回来"——等就等于把钥匙扔大街上。
2. **工具调用幻觉**：Agent 说"提交了 3 个文件"不代表真提交了，说"测试通过"不代表真跑了——重要操作要验证。
3. **四条检查是通用方法**，不需要安全背景，但能挡掉绝大多数麻烦。

## 原文精华（保留）

> Token 一旦出现在日志或终端输出里，就不能靠"捡回来"了——立即 revoke 重新生成。等就等于把钥匙扔在大街上。
>
> 你不需要成为安全专家。你只需要知道 Agent 会在哪些地方出错——然后在那些地方放一个检查点。花一个下午。比你想象的重要。

# 13 · AGENTS 工作流：从流程到状态图编排（导读）

来源：团长经历 13 ｜ 时间：2026 年中 ｜ 标签：状态图编排 / 动态路由 / 价值门控 / 3+1架构宪法
导读与核心命题
很多人把“智能体编排”做成了流水线工作流（Linear Workflow）：
节点 A 抓取 -> 节点 B 分析 -> 节点 C 输出，每个节点被强行塞入固定的动作。
这种流水线面对现实任务时必定崩溃——因为真实场景充满高熵：相同的输入，在不同的上下文、不同的信息充足度、不同的风险等级下，执行路径完全不同。
流水线（Workflow）：是一条传送带，教 AI “按顺序做什么”。
状态图编排（Orchestration）：是一张交通路网，节点不干具体活，节点负责**“依据当前态势，判断下一步往哪分流”**。
核心法则：编排者铺设路标与边界，智能体依据态势自主选道。
稳定性由编排者的“路标结构”锁死，广度与灵活性由智能体的“实时判断”释放。

AGENTS 节点设计规范（§0 - §5 拓扑流转）
一个具备工业级自愈与决策能力的智能体，其节点不是功能函数，而是六级决策关卡：
§0. 启动锚点（State Anchor）
职责：会话唤醒与上下文注水。
判定动作：加载用户身份、历史画像、当前系统可用资源。若环境缺失，直接初始化安全沙盒，绝不带着“脏状态”裸奔。
§1. 门禁入口（Input Router：猜还是问？）
职责：评估输入的“信息完整度”。
分支判定：
信息完备 ➔ 放行至通道选择；
关键信息缺失但可合理推断 ➔ 注入默认参数，带假设推进；
高风险关键信息缺失 ➔ 立即打断，向用户发起定向反问（Clarification）。
§2. 通道分流（Channel Dispatcher：快道还是深潜？）
职责：平衡响应延迟、Token 成本与任务复杂度。
分支判定：
快通道（Fast Track）：确定性事实查询、轻量闲聊、单步工具调用，毫秒级直出；
深潜通道（Deep Dive）：涉及多步推理、跨库合成、高风险操作，启动任务拆解器与子智能体协作网。
§3. 价值门（Value Gate：值不值得做？）
职责：解决智能体在复杂场景下的“行动犹豫”与“无效空转”（详见下节）。
判定动作：对即将执行的高成本/高风险动作进行收益与胜率仲裁。
§4. 规范执行（Execution Spec）
职责：工具调用与业务落地。
判定动作：严格依照契约（Schema）执行，调用结果必须接受强类型与边界校验。
§5. 异常与回滚（Fallback & Circuit Breaker）
职责：系统自愈底座。
分支判定：重试 ➔ 降级（返回兜底数据） ➔ 熔断（安全拒答并记录日志），绝不让底层异常直接向用户抛出。
核心机制：价值门（The Value Gate）与第 4 份文件
在编排复杂系统时，最常遇到的不是“AI 不会做”，而是**“AI 面对两难选择时反复横跳、算力空转”。为此，在核心三宪法之外，引入了第 4 份文件（价值仲裁协议）**。
1. 动手前三问（决策矩阵）

【 价值门仲裁矩阵 】
                     
                   把握度 (Certainty) 
                        高          低
                  ┌────────────┬────────────┐
             高   │   立即执行 │  挂起等待  │
                  │   (Execute)│   (Hold)   │
收益 / 价值       ├────────────┼────────────┤
(Impact)     低   │   快速跳过 │  果断不做  │
                  │   (Bypass) │   (Drop)   │
                  └────────────┴────────────┘
收益够不够（Impact）：做这件事能否实质性推进长期目标或解决当前阻塞？
把握够不够（Certainty）：当前拿到的上下文与证据链，支撑度是否达到阈值（如 > 80%）？
裁决动作：
收益高 + 把握高 ➔ 全力执行；
收益高 + 把握低 ➔ 挂起等待（补充搜集证据或向人类确认）；
收益低 + 把握高 ➔ 低成本极速通道处理，不浪费主算力；
收益低 + 把握低 ➔ 果断不做，主动熔断拒绝。

灵魂、边界、规范构成了智能体的三维坐标系，决定了系统的稳定上限；
价值门文件是应对复杂博弈时的动态仲裁补丁，负责在规则冲突时提供量化的优先级对齐，防止智能体死锁。
经验提炼与备忘法则
不要试图用代码写死执行步骤：写死步骤叫脚本；编排的艺术在于**“把控流转条件，放开执行路径”**。
状态图的每一个节点必须是可断言的：离开任何一个节点时，上下文必须产出明确的布尔值或枚举状态（如 VALIDATED, UNCERTAIN, BREACHED）。
区分基石与补丁：红线（边界）必须由代码和硬规则焊死；仲裁（价值门）交给大模型结合长期目标动态打分。底线不容商量，策略允许权衡。

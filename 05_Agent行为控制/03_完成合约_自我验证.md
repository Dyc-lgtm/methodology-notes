# 03 · 完成合约：Agent 自我验证（导读）

> 来源：行为控制·Completion Contracts

## 导读

Agent 说"我做完了"，能信吗？不能。Hermes 的 Completion Contracts 机制：**Agent 在宣称"完成"之前，必须通过实际测试——不是靠模型自我断言。**
(团长;我遇到的AI都做完了，我去看不满足不行，直接是错的。我最少每天都发生一两次，假如有某一次我实在忙了不看的话，这就是我的灾难,所以我越来越不相信，越来越小心翼翼，速度也开始放慢。如果时间充裕，甚至他的思考过程我也要看。当然，这个是低效的，不过重要的事情不得不小心，小心的确是能够发现更隐蔽的漏洞。但是这意味着放弃了大量的时间，在划算程度上，并不是什么事情都值得如此细致地去挖掘，因为这个效率太慢了。所以大部分场景我使用 AI 相互迭代。我的铁律是：绝对不发太过于绕脑袋的事情给 AI，要多为它们考虑。)
## 机制

```
Agent 声称完成 → pre_verify hook 触发 → 验证脚本（如 make test）
    → 通过？ → 放行
    → 不通过？ → 退回，返回具体指令
```

- `/goal` 命令内置完成合约
- `pre_verify` hook 支持自定义验证
- 必须跑过验证才算完成，不是"我说好了"就算

## 认知跃迁点

**本质同源**：任何"输出前插入一个不能跳过的检查点"。Completion Contracts 管编码质量（测试通过），三秒门管经验积累（这次有什么值得提炼）——同一个模式，换成不同检查脚本。

## 经验

1. **"自我断言"不可信**：Agent 说"提交了 3 个文件"不代表真提交，说"测试通过"不代表真跑——要有硬验证。
2. **可迁移模式**：把验证脚本换成"经验提炼检查脚本"，就是经验门的硬控版。
3. **输出前插检查点**：不拦输出，插检查点——完成推理后、输出前，强制过一个结构化步骤。

## 提炼

> Agent 在宣称"完成了"之前，必须通过实际测试——不是靠模型自我断言。
>
> 本质同源：都是在 Agent 输出前插入一个"你不能跳过"的检查点。

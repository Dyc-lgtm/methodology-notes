# 03 · 硬性编码指令与交叉审核（导读）

> 来源：教学法沉淀·质量保障 ｜ 给教学者用

## 导读

团长在课程设计中发现一个核心矛盾：**教得灵活 vs 教得准确**。太灵活，教学者（Agent）会跑偏；太死板，学生学到的只是教条。

解法是两个机制的组合：

1. **硬性编码指令** — 把教学底线焊死在系统里（不能讲错的、不能省略的、必须验证的），这些不交给 Agent 的自由发挥。
2. **交叉审核** — 输出必须经过多轮多专家审核，才能交付给学生。质量不是做出来的，是审出来的。

## 核心原则

- **60 元的定价，10000 块的课程底子**——低价不等于低质，教学质量靠审核撑。
- **硬性编码 == 不断生长的兜底规则表**——每次翻车就加一条规则，规则越多，翻车越少。
- **审核是质量的真正来源**——多专家多轮审核，比任何框架都管用。

## 给教学者的操作指南

### 硬性编码指令示例
```
1. 禁止编造未经验证的案例
2. 所有技术术语必须给出通俗解释（括号内比喻）
3. 学生问"这个工具怎么用"时，必须先问"需要我演示吗"
4. 每节课结束前必须确认学生理解，不能默认"懂了"
```

### 交叉审核流程
```
Step 1 ── 自检：教学者自己过一遍"我有没有违反硬性编码指令"
Step 2 ── 互审：另一教学者（或同梯队 Agent）独立检查
Step 3 ── 终审：核心内容由"教学法沉淀"库中的标准对照
```

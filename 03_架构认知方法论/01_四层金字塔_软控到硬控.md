# 01 · 四层金字塔：从软控到硬控（导读）★

> 来源：行为控制·Harness Engineering

## 导读

如何强制 Agent 按我们想要的方式思考？团长和镇星把行业方案理成"四层金字塔"——从软到硬，控制力逐层增强。

## 四层金字塔

```
④ DSL 规则引擎   ← 最硬。不仅控做什么，还控怎么想（AgentSpec，学术阶段）
③ 状态机/图路由  ← 流程结构焊死，LLM 跳不过去（LangGraph/Conductor，生产就绪）
② 工具调用拦截   ← 能拦错误动作，拦不住错误思考（Hermes TASK GATE）
① 提示词注入     ← LLM 可以无视（pre_llm_call，只是提醒）
```

## 逐层要点

1. **① 提示词注入（软控）**：每轮注入提醒。天花板：LLM 可选择性忽略——镇星 V2.1 工作流写了 11 步，0/11 遵守。结论：辅助提醒可以，不能做强制机制。
2. **② 工具调用拦截（硬控-工具层）**：能拦"不建 todo 就写文件"，拦不住"推演一半就跳输出"。**拦的是手，拦不住脑。**
3. **③ 状态机/图强制路由（硬控-流程层）**：LangGraph interrupt 节点间物理暂停；Conductor 用 YAML 写死编排、零 token。核心思想："编排应该是确定性的、可审计的，不要让 LLM 做路由决策。"
4. **④ DSL 规则引擎（硬控-思维层）**：AgentSpec 用"触发事件→判定条件→强制执行"三部分规则，唯一能同时控"做什么"和"怎么想"的方案（学术阶段）。

## 认知跃迁点

**Agent = Model + Harness**——在概率模型外包一层确定性控制平面。模型负责推理（概率），控制平面负责约束（确定）。

## 能教给学生什么

1. **软控 vs 硬控的边界**：提示词是"提醒"，钩子是"门"，状态机是"墙"——控制力完全不同。
2. **团长选 C（混合）**：日常执行用 Hermes+强化 TASK GATE，重大决策用 LangGraph，闲聊直接回。

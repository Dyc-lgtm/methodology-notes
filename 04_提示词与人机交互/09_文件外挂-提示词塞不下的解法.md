# 09 · 文件外挂：提示词塞不下的解法（导读）

> 来源：团长经历 09 ｜ 时间：2026 年初 ｜ 标签：文件外挂 / 三文件体系 / 从单体到分布式

## 导读

最早做智能体，团长把所有东西塞进一个提示词：角色、规则、边界、流程、禁止项，几千字。越加越多，规则开始打架，改一条要通读全文，改了一处三行外的规则被悄悄覆盖。

N8N 教过他"数据流"——数据在节点间流动，每个节点只做一件事。为什么 Agent 的规则不能这样？于是开始拆文件。

## 认知跃迁点

**编排的基本单位不是提示词，是文件**。提示词是单体的，行为是分布式的——所以要把"它是谁 / 什么不能做 / 怎么干活 / 有什么技能 / 什么触发什么"拆成独立文件，运行时挂载。

## 能教给学生什么

1. **为什么要拆文件**：改 SOUL 不影响 CONSTITUTION，加技能不影响人格，出了问题定位到具体文件（灵魂偏了？边界松了？流程断了？）。
2. **拆分的五个维度**：它是谁（SOUL）/ 什么不能做（CONSTITUTION）/ 怎么干活（AGENTS）/ 有什么技能（Skills）/ 什么触发什么（路由）。
3. **好解法会殊途同归**：团长自己摸出的"文件外挂"，和 Hermes 作者的 Role/Skill/Constitution 不谋而合——是问题逼出来的必然答案。

## 原文精华（保留）

> 规则之间开始打架。改一条要通读全文……等到 Agent 行为出了问题，回去翻提示词，翻半天才发现两条规则互相矛盾。
>
> 提示词是单体的。而智能体的行为是分布式的。
>
> 之前：一个 Agent = 一个巨型提示词……调试成本随规则数量指数增长。
> 之后：一个 Agent = 核心文件 + 外部挂载文件。改 SOUL 不影响 CONSTITUTION。
